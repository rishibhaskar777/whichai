# 0010: English and Hindi

Status: accepted

## Context

The interface should work in English and Hindi. Only two languages are planned, the language must be known on the server so there is no flash, and the project avoids new dependencies ([0006](0006-zero-cost.md)).

## Options

| Option                  | For                                                                           | Against                                                                                      |
| ----------------------- | ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `next-intl`             | Mature, routing and formatting built in, free and MIT licensed                | A dependency plus plugin and request configuration for two languages; routing we do not want |
| Typed dictionary module | No dependency; the compiler checks every Hindi string exists; about 100 lines | Plural and formatting helpers are ours to maintain                                           |

## Decision

A small typed dictionary in `src/lib/i18n/`. `en.ts` is the source of truth, `hi.ts` is typed to the same keys, and `createI18n(locale)` returns `t`, `tn` for plurals, `rich` for placeholders that are elements, and `Intl` formatting (`en-IN`, `hi-IN`). A test checks that both languages have the same keys and the same placeholders.

- The language lives in a `lang` cookie. The root layout reads it, sets `<html lang>` and gives the client provider its first value. Settings writes the cookie, switches the provider and calls `router.refresh()` so server components follow.
- URLs do not change with the language.
- **Font:** Onest has no Devanagari, so Noto Sans Devanagari (SIL Open Font License) is loaded through `next/font/google`, which downloads it at build time and serves it from this site. It is not preloaded; the browser fetches it only when a page contains Hindi.
- **Catalogue content** (tool summaries, workflows, plan text) stays in English, and Hindi mode says so. Goal understanding also works only on English words, and the home page says that too.

## Consequences

- The Hindi text has not been reviewed by a native speaker. It is marked "needs native review" here and in the roadmap, and `hi.ts` says so in its header.
- Adding a language means adding a dictionary, a locale value in `locales.ts`, and checking the font covers it.
- Brand and tool names stay in Latin script by design.
- Translating catalogue content would multiply the data to verify ([VERIFYING-DATA.md](../VERIFYING-DATA.md)), so it waits until records are verified.
